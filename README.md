# Notarial Audit-Log Framework Demo
This repository serves as an accompanying artifact for my master's thesis on
audit logging in the notarial domain, completed as part of the [Business Informatics](https://www.uu.nl/en/masters/business-informatics)
programme at Utrecht University in collaboration with the [KNB](https://www.knb.nl/) (Royal Dutch Association of Civil-law Notaries).

## Overview
The demo contains an interactive webpage of a three-layer audit-logging framework for
the notarial domain. It steps through example notarial processes and shows how
logged events advance through the framework's layers and gates, with tampered
events breaking specific conditions.

This repository provides the demo with example governance rules and process
definitions. You can rebuild the project with custom data.

## Run

The app is fully static, so serve the `frontend/` directory with any web server:

```bash
cd frontend
python3 -m http.server 8000
# then open http://127.0.0.1:8000
```

No Python is needed to run the demo. It is only used to regenerate `states.js`
(see below). Best viewed on a display of at least 1600×800.

## How to update

Every reachable state is precomputed by `build_states.py` into
`frontend/states.js`. At runtime nothing happens server-side.

The UI is plain JavaScript: the `.jsx` sources are compiled ahead of time into
`frontend/components.js` and `frontend/app.js`, so the browser loads no compiler.

Two build steps regenerate the committed artifacts:

```bash
./venv/bin/python build_states.py   # after editing governance/ or processes/
node build_frontend.cjs             # after editing the .jsx sources
```

## Layout

```
frontend/      the app: static, self-hosted JS and fonts, no third-party requests
  states.js          generated by build_states.py; all (scenario, cursor) states
  *.jsx / *.js       UI sources and their generated, browser-ready output
governance/    the rulebook: principles, specs, schemas (frozen, match the thesis)
processes/     scenario walkthroughs and tamper rules
framework/ domain/ api/ emitters/   Python that computes the states at build time
build_states.py    precomputes every state into frontend/states.js
build_frontend.cjs  compiles the .jsx sources into plain .js
build/         build-only tooling (Babel standalone), not deployed
```

## Scenarios

Selectable in the top bar are three example processes:

| key | process |
|---|---|
| `deed` | Transfer of a deed (running example) |
| `register` | Register Notariaat consultation |
| `cdr` | CDR deed consultation |

## Disclaimer
This demonstration was developed with the assistance of AI tools and with limited
focus on code quality, as its purpose is to serve as a simple interactive demo.
The processes shown are exemplary processes drawn from the notarial domain, not
exhaustive or authoritative descriptions of actual notarial workflows.
